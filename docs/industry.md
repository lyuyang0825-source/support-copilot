# 03 · AI 客服：问题不是“像不像人”，是“该不该它说”

## 行业问题

2025 年的公开数据与案例：

- 上海市消保委 2025 年受理 **AI 客服相关投诉 1087 件**；
- 黑猫投诉平台“转人工”相关投诉累计 **3 万+**；
- 某在线教育公司上线 AI 客服后：日均对话 **2000 → 8000**，满意度 **-15%**，转人工率 **20% → 45%**，客诉 **+30%**；
- Gartner 判断约 **60%** 的客服机器人只能解决不到一半的问题；
- 生成式 AI 对复杂售后场景的理解准确率仍 **不足 60%**。

更关键的是监管：新国标《顾客联络服务 人工与智能客户服务协同要求》于 **2026-09-01 实施**，明确要求：

1. 智能客服处理**标准化**问题；
2. **复杂问题、涉及安全**的问题转人工；
3. 人机切换时**同步上下文**，不得让用户重复描述；
4. **价格、退款、赔偿、合同变更**由人工最终确认。

这四条基本定义了产品形态：**AI 不是“替代人”，而是“把人从重复问题里解放出来，并把人送到该去的地方”**。

## 可被 AI 解决的产品方向

| 方向 | 解决什么 | 本仓库 |

## support-copilot 的取舍

- **只答知识库里有答案的问题**：BM25（中文二元组 + 同义词扩展）召回，分数低于阈值直接拒答；
- **承诺词零容忍**：出现“保证/一定/立刻到账/全额赔付”等词，一律降级为“需人工确认”；
- **数字必须溯源**：回答里的天数、金额、次数要能在命中的知识条目中找到，否则视为编造；
- **强制人工规则**：涉及退款、赔偿、账号冻结、价格争议、人身安全、投诉升级，进入 `answer_with_human`；
- **不重复问**：交接摘要带 `do_not_reask` 列表，用户已经说过的订单号/账号不再问；
- **会话质检**：`--eval` 对整段会话打分，输出引用覆盖率、越权承诺、该转未转、重复询问、下一步是否明确。

demo 6 条对话的结果：

| 用户 | 决策 | 置信度 |
| --- | --- | --- |
| 退款多久到账 | `answer` | 0.88 |
| 我要退款 | `answer_with_human` | 0.88（建工单，缺 order_id） |
| 价保几天？帮我补差价 | `answer_with_human` | 0.94 |
| 账号被冻结 | `answer_with_human` | 0.83（缺 account_id） |
| 发票抬头怎么改 | `answer` | 0.85 |
| 你们支持火星配送吗 | `refuse` | 0.00（范围外，直接转人工） |

规范会话质检 **100 分**，问题会话 **10 分**——差距来自重复询问、越权承诺、该转未转。

## 怎么衡量

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 自助解决率 | 无需转人工即闭环的会话占比 | 标准化问题 ≥ 60% |
| 转人工准确率 | 转人工中“确实该转”的比例 | ≥ 85% |
| 重复询问率 | 交接后仍问已提供信息 | < 5% |
| 承诺违规率 | 出现越权承诺的会话占比 | 0（硬门禁） |
| 引用覆盖率 | 回答中带知识条目引用的比例 | ≥ 90% |
| CSAT | 会话满意度 | 不低于纯人工基线 |

## 合规与边界

- 按新国标做**人机协同**：AI 解释规则、收集材料、建工单，人工做最终确认；
- 价格/退款/赔偿/合同变更**不由 AI 拍板**；
- 个人信息最小化：订单号、账号在日志中脱敏；不把对话用于训练除非另行授权；
- 保留“AI 身份告知”与“转人工入口”，不得故意隐藏人工入口。
