# 模型接入卡（不是已训练权重）

这个仓库**不发布任何训练好的模型权重**。它发布的是一层可替换的 OpenAI 兼容适配器、一套 200 条开发评测、以及一本说清楚模型能做什么、不能做什么的“模型卡”。

如果你在找“下载一个客服大模型”，这里没有；如果你要的是“把一个开源模型安全地接进客服链路，并且能证明它没有变坏”，这里就是。

## 怎么接

```bash
export LLM_BASE_URL="https://api.siliconflow.cn/v1"   # 任何 OpenAI 兼容服务
export LLM_API_KEY="sk-..."                           # 本地 Ollama 可留空
export LLM_MODEL="Qwen/Qwen2.5-7B-Instruct"

python3 -m support_copilot.cli -q "退款多久到账" --llm
python3 scripts/run_evals.py --llm
```

本地 Ollama：

```bash
ollama serve
ollama pull qwen2.5:7b-instruct
export LLM_BASE_URL="http://localhost:11434/v1"
export LLM_MODEL="qwen2.5:7b-instruct"
```

没有 GPU、也没有 API key 时，先用协议桩验证链路：

```bash
python3 scripts/mock_llm_server.py --port 8123
export LLM_BASE_URL="http://127.0.0.1:8123/v1"
python3 -m support_copilot.cli -q "退款多久到账" --llm
```

协议桩只回显“规则答案”，不生成新内容，因此只能验证 HTTP、JSON、超时、校验与回退，不能证明模型效果。

## 模型在链路里的位置

```text
用户问题
  → 意图识别（规则）
  → BM25 + 意图对齐召回（规则）
  → 置信度 / 强制人工判断（规则）
  → 模型只改写“已命中的知识答案”
  → 数字溯源、承诺词、重合度三道校验
  → 通过：输出润色版；不通过：回退知识原文
  → 引用行、工单、交接摘要仍由规则层生成
```

模型**不决定**动作、不选择知识、不生成引用、不写工单、不判断该不该退款。它只负责把已经确认的事实说得更像人话。

## 输入与输出契约

模型收到一段 JSON：`用户问题`（已做 PII 脱敏）、`知识标题`、`规则答案`、`动作`。

硬约束：

- 不新增数字、时间、金额、比例、条件、承诺；
- 不弱化“仅 / 除外 / 最多 / 需 / 不 / 无法”；
- 不输出“依据：”，引用行由系统追加；
- 不自称 AI，不说“我会为您跟进”；
- 无法安全改写时原样返回规则答案。

三道校验在 `llm.validate_polish()`：

1. 承诺词扫描（保证、一定、绝对、100% 等）；
2. 数字溯源 + 数字集合比对（知识原文没有的数字一律拒绝）；
3. 与知识原文的词元重合度（低于 20% 认为跑题）。

任何一道不过，`agent._polish()` 回退原文，并在 `Answer.notes` 写明 `llm 未采用：原因`。

## 评测协议

- 开发集：`data/evals/cases_200.json`，12 类，200 条；
- 指标体系：动作准确率 + 期望知识命中率；
- 规则基线：199/200（99.5%），唯一未过是“到货时间怎么算”被保守降级为需人工确认；
- 模型组：同一套用例加 `--llm`，必须同时报告“润色生效条数”和“回退条数”；
- 真实上线前：用真实脱敏会话重建测试集，开发集不能替代真实分布。

这套 200 条是**合成开发集**，用于防回归，不用于证明线上效果。

## 如果以后要训练

最低配置：

| 项 | 最低要求 |
| --- | --- |
| 数据 | 每个任务 2k–5k 条“问题 + 知识 + 合规回复”，人工复核 ≥10% |
| 算力 | 1×RTX 4090 24GB 或 A100 40GB，QLoRA 7B |
| 时间 | 2–3 epoch，几小时到一天 |
| 评测 | 200 条黄金集，base / tuned / 规则三组对比 |
| 合规 | 医疗、金融等敏感行业需脱敏与伦理审批；客服需留存对话授权记录 |

训练目标不是“让模型知道退款几天”，而是“让模型在给定知识下稳定遵守引用、拒绝越权、该转人工就转”。如果数据里没有这些负例，训出来只会更会说，不会更可靠。

## 不该用的场景

- 让模型直接决定退款金额、赔偿方案、账号封禁；
- 让模型在没有知识命中的情况下自由回答；
- 用合成数据训出的权重宣称“达到生产可用”；
- 把含手机号、订单号、地址的原始对话直接发给第三方托管服务。
